# localization-seo — Sellzen

Read `../../CONTEXT.md` first (§2 i18n row, §6 R10 hash routing).

## Scope
Make Sellzen usable in every target language and findable in Google/Yandex in Uzbek, Russian and the other Central Asian languages.

## Required repository inspection
1. Client i18n: `src/i18n/index.ts` (`LANGS = uz, en, ru, kk, ky, tg`, `L`, `useT`, language detection/storage), `src/i18n/uz.ts`, `src/i18n/catalog.json` (generated), `src/i18n/format.ts` (numbers, dates, currency), `src/components/LangPicker.tsx`.
2. Tooling: `scripts/i18n/codemod.ts` (wraps/guards strings), `scripts/i18n/extract.ts` (catalog), `npm run i18n:check`.
3. Server translations: `server/i18n.ts` (`TARGETS = en, ru, kk, ky, tg`, DB-stored dictionaries, `coverage`, `translateMissing` via AI, `lastRejected`, `trServer`), quality gate `server/i18nQuality.ts`, Studio translation UI; `/api/i18n` publishes only languages with ≥ 98 % coverage.
4. SEO assets: `index.html` (title/description/OG/Twitter/canonical `https://sellzen.uz`), `public/robots.txt`, `public/sitemap.xml`, `public/vositalar/*.html` (band calculator, IELTS↔CEFR/Multilevel, speaking/writing topics), generator `scripts/seo/gen.ts` + `gen.test.ts` (pages must match content data), `public/manifest.webmanifest`.
5. Server static handling: `server/static.ts` (how `.html` paths, caching and SPA fallback are served).
6. Spec: `docs/audit/master-spec-v2/MULTILINGUAL_ARCHITECTURE.md`.

## Localization standards
- Source language is Uzbek (Latin) in `L()`; never hard-code UI text. Placeholders `{0}` keep word order flexible for Russian/Kazakh grammar.
- Machine/AI translations are drafts: `i18nQuality.ts` rejects broken placeholders/markup; human review recommended for ru first (largest market). Mark reviewed vs AI-drafted in the DB if you add that field — don't claim human review that didn't happen.
- Learning explanations: the product promise is "learn English with explanations in your native language". Lesson explanations are authored in Uzbek; delivering them in ru/kk/ky/tg must go through the same catalog/DB translation path (not separate duplicated lesson files) unless the methodologist decides a language needs bespoke explanations.
- Scripts: Uzbek Latin primary (Cyrillic Uzbek is a possible later variant — keep code `uz` = Latin), Kazakh Cyrillic (Latin transition in progress — decide with owner), Tajik Cyrillic, Kyrgyz Cyrillic. Turkmen (`tk`) is not in `LANGS` yet — adding it means `LANGS`, `TARGETS`, STT code map and quality checks.
- Formatting: `fmtSum` for UZS; other markets need currency per country (KZT, KGS, TJS, TMT) — design a country config, don't sprinkle conditionals.

## SEO standards
- **The SPA uses hash routes** (`#/…`) — invisible to search engines as separate pages. Indexable content must be **static HTML** generated at build time (the `public/vositalar` pattern) or real path routes served by `server/static.ts`. Don't promise SEO from SPA pages.
- URL scheme for multilingual static pages: `/{lang}/{slug}` (e.g. `/ru/ielts-band-kalkulyator`), keep existing Uzbek URLs stable (`/vositalar/*.html`) or 301 them.
- Each page: unique `<title>` (≤ 60 chars) and meta description, `<link rel="canonical">` to itself, `hreflang` alternates for every language version + `x-default`, OG tags, one h1, real content above the fold (no thin pages), internal links to related tools and to the app CTA (`/#/placement`).
- Structured data (JSON-LD) only where truthful: `FAQPage` for real FAQs, `WebApplication`/`SoftwareApplication` for the app, `BreadcrumbList`; **no** fake `Review`/`AggregateRating`, no `Course` claims of accreditation.
- Programmatic SEO from existing data (band tables, speaking topics, writing prompts, Multilevel format) — generated by `scripts/seo/gen.ts`, tested by `gen.test.ts` so pages never drift from content. Avoid near-duplicate pages per city/country unless content truly differs (country exam rules, prices, payment methods).
- Sitemap lists every indexable URL with `lastmod`; robots allows them; never index app routes or `/api/`.
- Keyword research: state the source of any search-volume claim (tool + date). If you have no data, present hypotheses (e.g. "ielts band calculator", "multilevel ball hisoblash", "ielts speaking part 2 mavzulari 2026", "cefr b2 nechchi ball", Russian equivalents) as hypotheses.

## Project-specific rules
- Canonical host is `https://sellzen.uz` (`SITE` in `scripts/seo/gen.ts`, `index.html`); never emit `bandly-production.up.railway.app` in SEO files (`brand.test.ts` fails).
- Generated files (`public/vositalar/*.html`, `sitemap.xml`, `robots.txt`) are build outputs of `scripts/seo/gen.ts` — edit the generator, not the HTML.
- IELTS↔CEFR mapping uses the ielts.org source recorded in `gen.ts` (`IELTS_CEFR`, read 2026-11-18); Multilevel facts come from `UZ_MULTILEVEL` in `examFormats.ts`. Don't restate exam facts from memory on SEO pages.
- A language becomes selectable only at ≥ 98 % coverage (`/api/i18n`); don't force-enable partially translated languages.
- Turkmenistan: no `tk` locale yet and market specifics unverified — treat as research, not implementation.

## Workflow
1. Identify language/market and intent (informational tool, comparison, exam info, conversion page).
2. Check existing pages and data sources; extend `gen.ts` rather than hand-writing HTML.
3. Implement; run `npm run seo:gen`, `npx tsx scripts/seo/gen.test.ts`, `npm run i18n:check`, `npx tsx scripts/build/brand.test.ts` (scans `public/vositalar`).
4. Validate HTML (titles unique, canonical/hreflang reciprocal, sitemap entries) with a small script; report results.

## Testing requirements
Extend `scripts/seo/gen.test.ts` for new page types (content parity, canonical, hreflang reciprocity, sitemap inclusion). i18n changes keep `src/i18n/i18n.test.ts`, `src/i18n/format.test.ts`, `server/i18n.test.ts`, `server/i18nQuality.test.ts` green.

## Common mistakes to avoid
- Expecting Google to index `#/` routes.
- Duplicating lesson content per language instead of translating via the pipeline.
- Auto-translating SEO pages without review and publishing them as authoritative.
- Missing reciprocal hreflang or canonicals pointing to the wrong language.
- Fake structured data or "official IELTS partner" wording.

## Deliverables
Language/market plan, generated pages + tests, sitemap/robots updates, metadata table, and an organic-opportunity list with clearly labelled data sources or hypotheses.
